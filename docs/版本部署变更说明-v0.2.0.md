# 版本部署变更说明 v0.2.0

> 发布前请先跑「验收清单」；版本号以实际发布为准（当前分支功能目标 0.2.0，
> manifest.json / package.json / Cargo.toml 在发版提交时统一 bump）。

## 新增：Microsoft 365 / Outlook.com（Graph API）

- **背景**：微软已对 Microsoft 365 与 Outlook.com 停用 IMAP/SMTP 基本认证，
  原有 `outlook` 预设的纯密码登录在大部分租户不可用。新增 Graph API 传输
  （收发全量对齐 IMAP 账户），与 IMAP 共用本地缓存，会话/搜索/阅读/附件/
  草稿/发件箱体验一致。
- **授权**：OAuth2 授权码 + PKCE；sidecar 在 `127.0.0.1` 随机端口接收回环
  回调；`offline_access / Mail.ReadWrite / Mail.Send / User.Read` 委托权限；
  refresh_token 走系统凭据库（或本地加密兜底），access_token 只驻内存、
  到期前自动刷新且轮换后立即回存。
- **自备 Azure 应用**（用户操作，见 README §1.1 五步）：多租户 + 个人账户、
  「移动和桌面应用程序」平台重定向 `http://localhost`、四个委托权限。
- **同步**：文件夹 `wellKnownFolderName` → 本地 role；首拉最新 N 封
  （沿用「主要/全部文件夹」范围与 initial_limit）；`messages/delta` 增量，
  deltaLink 断链自动重建；远端删除/旗标变化经增量回放，本地未推送改动
  （`pending_flags`）优先。
- **发送**：MIME 建草稿（保留 Message-ID/References/In-Reply-To 线程头）
  + send，自动落「已发送」；>4MB MIME 自动回退 JSON 草稿 + 附件上传会话
  分片；沿用 25MB 单附件 / 40MB 总量上限。

## 新增协议方法

| 方法 | 说明 |
| --- | --- |
| `account/oauthBegin` | `{tenantId, clientId}` → `{authorizeUrl, state, expiresIn}` |
| `account/oauthStatus` | `{state}` → `{status: pending\|done\|failed\|expired, refreshToken?, error?}`（只读，不消费） |
| `account/oauthCancel` | `{state}` → 取消等待中的授权 |
| `account/add` / `account/update` | Graph 账户：`provider:"graph"` + `tenantId` + `clientId` + `oauthState`（认领 refresh_token），无密码字段 |
| `mcp/tools` / `mcp/call` | MCP 工具面：纯发现 + 调用（6 工具，见下「新增：AI 工具（MCP）」） |
| `connection/test` / `connection/connect` / `connection/disconnect` | DBX 连接管理生命周期（见下「新增：DBX 连接管理（connection-provider）」） |

## 新增：M365 纯后台接入与机密客户端

- **纯后台接入（client_credentials）**：`account/add` 走 `provider:"graph"` +
  `clientSecret` + `userId`（无 `oauthState`）→ `auth_type:"oauth2_app"`；
  无浏览器交互，应用令牌直访 `/users/{userId}/...`。Azure 应用需配置
  Mail.ReadWrite / Mail.Send / User.Read 的「应用程序」权限并管理员同意。
  令牌无 refresh_token，过期自动重取；`clientSecret` 只存系统凭据库
  （SQLite 仅存引用列 `client_secret_ref`），`account/list` 不回传任何凭据。
- **机密客户端授权码**：浏览器授权流程（`oauthBegin`/回调）可选携带
  `clientSecret`，token 交换与刷新带上它；向导两种模式均可填写。
- 数据库 `user_version` 2 → 4：`accounts` 增 `user_id`、`client_secret_ref`
  （与连接管理的 v3 合并交付）。
- 验证：`scripts/real-m365-check.mjs`（真实租户连通性 + 应用令牌 + 只读邮箱探测）
  与 `scripts/real-m365-app-check.mjs`（插件本体真实端到端，只读），凭据经
  环境变量注入；`sidecar-check` 新增「纯后台接入」节（mock client_credentials）。
  无人值守跑真实验收时可设 `DBX_MAIL_SECRET_FILE=1` 强制本地加密通道，
  避免新二进制首次读取钥匙串触发 macOS 授权弹窗。

## 新增：AI 工具（MCP）

- `manifest.json` 声明 `mcp` 贡献点（`external_tools: true`，工具集
  `mailbox-read` / `mailbox-write`）；`mcp/tools` 只做发现，`mcp/call` 逐参数
  校验并复用既有引擎。
- 工具：`folder_list` / `mail_list`（游标分页）/ `mail_read`（纯文本正文）/
  `mail_flag` / `mail_move` / `mail_send`（`dryRun` 两阶段预览，真正发送入
  发件箱队列，不支持附件）。
- 凭据红线：参数与输出不含密码/令牌；工具定义有敏感词断言；宿主注入的
  `connectionId` 只接受、不透传。

## 新增：DBX 连接管理（connection-provider）

- `manifest.json` 声明 `connection-provider` 贡献点（`database_type: "mail"`），
  并声明 `capabilities: ["test","connect","disconnect"]` 与 `workbench`（宿主从
  连接打开工作台的必需字段，缺失会报「does not declare a workbench」）。
  表单字段 `kind`（`imap` / `graph`）、邮箱、IMAP/SMTP 服务器组、Graph 组
  （`client_id`、`tenant_id` 默认 `common`、`auth_mode` 浏览器授权/纯后台、
  纯后台态追加 `client_secret`（password, binding secret）与 `user_id`）；
  表单键按宿主标识符规范用 snake_case，sidecar 在 `connection/*` 解析处映射到
  `account/add` 的 camelCase 参数。
- `connection/test`：IMAP/SMTP 探测；`graph` 浏览器态不做网络探测、缺
  `client_id` 直接失败；纯后台态用 client_credentials 换一次应用令牌作验证。
  `connection/connect`：以 `connection.id` 幂等建会话并复用同步引擎；Graph
  浏览器态只建账户壳，浏览器授权仍在插件内「重新授权」完成；纯后台态换令牌
  成功后建 `oauth2_app` 账户并后台首拉，`client_secret` 只在内存会话表。
  `connection/disconnect`：停会话、解绑 `host_bound`、保留本地缓存。
- **凭据不落盘**：宿主连接的密码只在生命周期请求与 Sidecar 内存会话表中出现，
  不写本地密钥库/SQLite；既有 `account/*` 方法与向导账户行为零改动（以
  `hostBound` 标记区分来源）。

## 数据库迁移

- `user_version` 1 → 2：`accounts` 增 `provider/auth_type/tenant_id/client_id`；
  `messages` 增 `remote_id`；`mailboxes` 增 `remote_id/sync_state`（Graph
  folder id 与 deltaLink）。旧库自动升级，IMAP 账户行为不变。
- `user_version` 2 → 3：`accounts` 增 `host_bound/host_connection_id`
  （DBX 连接管理来源标记；旧行默认未绑定，行为不变）。

- `scripts/mock-graph.mjs`：本地 OAuth2 + Graph mock（冒烟专用，不出网）。
- `npm run sidecar-check`：69 项检查，其中 Graph 全链路 / M365 纯后台 / MCP
  数据用例 / 纯后台连接生命周期各节要求 **debug 构建**（`npm run backend:dev`）；

  解析与轮换、delta 解析、role 映射、迁移升级/幂等、remote_id 去重、MCP
  工具形状/参数校验/dry_run、连接生命周期解析与幂等会话表、Graph 纯后台
  auth_mode 解析等。

## 已知差异与限制

- Graph 账户「已回复」标记为近似值（`In-Reply-To` 非空视为已回复），
  Graph 列表不提供 answered 旗标。
- >4MB 附件走 JSON + 上传会话回退路径，该路径无法设置 References 等线程头
  （微软限制），会话归并可能断链。
- 访问令牌在同步中途被吊销（管理员撤销/改密）时会报 401，需要用户手动
  「重新授权」；不会自动无限刷新。
- 受限租户可能要求管理员同意授权；Windows 首次授权可能弹防火墙允许提示
  （本地回环监听）。
- `outlook` IMAP 预设保留但 hint 已提示基本认证停用，引导走 Graph。
- 连接管理器创建的 Graph 账户在插件内授权前不同步（不进周期巡检），
  `connection/test` 对 Graph 不做网络探测。
- MCP `mail_send` 不支持附件；`mail_read` 输出为纯文本（HTML 自动转文本），
  不展示附件内容。

## 真租户手动验收清单（发版前执行）

> 本机开发环境无 M365/Outlook.com 账户，以下场景需真实租户验证：

- [ ] 个人 Outlook.com：注册 Azure 应用（个人账户类型）→ 向导授权 → 首次同步
      → 阅读/搜索/附件 → 撰写发送 → 已发送回流。
- [ ] 组织 M365：同上；确认 deltaLink 二次同步只拉增量（网络面板或日志）。
- [ ] 受限租户（禁用用户同意）：确认授权页出现「需要管理员批准」的明确提示，
      插件报错文案可读。
- [ ] 大附件发送（>4MB，≤25MB）：确认走上传会话回退且发送成功。
- [ ] token 失效场景：租户管理员撤销授权 → 同步失败文案可读 → 重新授权恢复。
- [ ] 五平台打包（CI）：`rust-toolchain.toml` 已移除，CI 按 runner 原生 stable
      工具链构建（Windows 为 MSVC；Windows 本机 gnu 由该机器 `rustup default`
      自行设置）；Graph 冒烟节在 release 包中自动跳过。
- [ ] 连接管理器：建 Graph 账户（clientId+邮箱）→ connect → 插件内重新授权
      → 首拉同步 → disconnect 后数据保留。
- [ ] 外部 dbx MCP 接入：`mail_list`/`mail_read` 走真实账户；`mail_send`
      dryRun 预览后真实发送一封并撤销窗口内可撤回。
